# Working rules

- Complete the authorized outcome; preserve unrelated work. Read the relevant implementation and callers before editing. Reuse existing patterns and dependencies.
- The parent orchestrator may delegate to at most three concurrent subagents with disjoint file ownership. Give each exact contracts, inputs, acceptance criteria, and model/effort settings. Workers report conflicts instead of editing another owner's files.
- Only the parent runs dependency installs, builds, Cargo commands, tests, browser automation, rendering/conversion jobs, benchmarks, packaging, or other expensive operations. Queue checks and run one dependency-ordered batch per integration milestone, never after every worker task. Workers may read/search, edit assigned files, and propose checks.
- The parent owns shared contracts, entry points, manifests, lockfiles, integration, and Git commits. Workers must not commit, stage, reset, or change branches. No recursive delegation unless the parent explicitly assigns it within the same concurrency limit.
- Write the smallest clear implementation that satisfies the contract. Prefer explicit types, bounded allocation, predictable state transitions, and reliable cleanup. Avoid speculative abstractions, dependencies, clever compression, and unmeasured performance claims.
- Add regression coverage for meaningful logic, security, data integrity, and concurrency risks. Extend the nearest relevant test file first; create a file only for a distinct responsibility. Skip trivial getters, styling snapshots, and tests that merely repeat implementation.
- Default to no inline comments; explain only non-obvious constraints. Keep status messages to one sentence when information changes. Worker reports contain changed paths, contract changes, risks, and requested checks; no work diary.
- Validate external inputs and privileged IPC; bound sizes, durations, and queues. Handle expected absence explicitly and propagate actionable errors without secrets. Await resource shutdown before reuse.
- Use local/free resources for development. Paid APIs or cloud credits are allowed only for an explicitly authorized live benchmark, or an explicit user exception for the particular non-live work. A demo or development subset is not automatically a benchmark. Do not expose credentials or launch metered SDK sessions for smoke checks.
- Camera capture requires explicit in-app consent. Rehearsal input must remain visibly synthetic. Do not claim camera-derived brain activity, diagnosis, measured airflow, or beat timing derived only from averaged pulse rate.
- Commit small coherent completed chunks frequently with a single-line message in the form `<type>: <Imperative description>`. Author and committer: `David Condrey <david@writerslogic.com>`. Inspect the diff and stage explicit paths; record any pending batch verification honestly. Never claim checks passed before running them.
- Local commits are authorized. Remote creation, pushing, publishing, and sending messages require task authorization. Never rewrite unrelated history or include secrets, local recordings, proprietary SDK binaries, or restricted assets.
- Keep execution prompts outside the repository. Record technical decisions and verification evidence in `docs/CONTEXT.md`; keep asset provenance with the assets. Resolve commands from project manifests; format only touched files using established tooling. After two failures with the same cause, inspect the cause and change approach.
